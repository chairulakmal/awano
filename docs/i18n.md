# Internationalization and mobile

The implementation reference for Awano's next-iteration internationalization (English and Japanese) and the mobile-browser support planned alongside it. The single constraint that shapes every decision here: i18n and mobile are UI-layer concerns only, so the service layer, authorization logic, Prisma schema, and business rules stay locale- and device-agnostic. Below: locale routing and detection, message catalogs, Japanese font loading, IME-aware inputs, the locale switcher, date and number formatting, then the mobile card and drawer layouts.

This file is the "how". What to build and in what priority order lives in the root [TODO.md](../TODO.md) (section 6 for i18n, sections 2 and 3 for mobile). Recruiters viewing the demo are predominantly Japanese, which is the reason this work is prioritized: v1 shipped English-only.

## Routing and locale detection

Wrap the entire `app/` directory under `app/[locale]/`. Every route gains a locale prefix: `/tickets` becomes `/en/tickets` and `/ja/tickets`.

```
app/
  [locale]/
    login/
    tickets/
    desk/
    admin/
    super/
    profile/
```

The `proxy.ts` route-guard matchers update from `/desk/*` to `/:locale/desk/*`.

Locale detection order, resolved in `proxy.ts`:

1. URL prefix: `/en/…` or `/ja/…`
2. `NEXT_LOCALE` cookie set by the switcher
3. `Accept-Language` request header
4. Default: `en`

Bare `/` redirects to the detected locale.

## Message catalogs

```
messages/
  en.json
  ja.json
```

Flat keys namespaced by component: `login.emailLabel`, `tickets.noTickets`, `desk.internalNote`. Status enum display names (`OPEN` maps to "Open" or "対応待ち") live here too. Ticket `subject` and `body` are user content and are not translated.

## Japanese font

`Noto Sans JP` loaded via `next/font/google`. In `output: "standalone"` mode Next.js self-hosts the font at build time, so there is no Google CDN request in production and the font is included in the standalone output automatically.

Load it only when the locale is `ja`, to avoid shipping roughly 1 MB of Japanese glyphs to English users:

```ts
// src/app/[locale]/layout.tsx
import { Noto_Sans_JP } from "next/font/google";

const notoSansJP = Noto_Sans_JP({
  subsets: ["latin"],
  weight: ["400", "500", "600"],
  display: "swap",
});

export default function LocaleLayout({ children, params: { locale } }) {
  return (
    <html lang={locale} className={locale === "ja" ? notoSansJP.className : ""}>
      {children}
    </html>
  );
}
```

## Japanese form input (IME)

Japanese text entry goes through an IME: the user types romaji, selects kanji or kana candidates, then confirms. During composition, `onChange` fires on every keystroke before the final character is committed.

Problem: the debounced search in `DeskSidebar.tsx` fires mid-composition, sending incomplete romaji to the server (for example `"vi"` instead of `"ビザ"`).

Fix: suppress the debounce timer during IME composition using the browser's `compositionstart` and `compositionend` events.

```ts
const isComposing = useRef(false);

<input
  onCompositionStart={() => { isComposing.current = true; }}
  onCompositionEnd={(e) => {
    isComposing.current = false;
    handleSearch(e); // fire once composition is confirmed
  }}
  onChange={(e) => {
    if (isComposing.current) return; // suppress during composition
    handleSearch(e);
  }}
/>
```

This applies to any debounced or auto-submitting input: ticket search, any future typeahead. Regular form submits (press Enter, click button) are unaffected, since the browser will not submit during active composition.

## Locale switcher

A `LocaleSwitcher` client component placed in `Header.tsx` alongside `UserMenu`.

```ts
"use client";
import { useRouter, usePathname } from "next/navigation";

export function LocaleSwitcher({ locale }: { locale: string }) {
  const router = useRouter();
  const pathname = usePathname();

  function switchTo(next: string) {
    const newPath = pathname.replace(`/${locale}`, `/${next}`);
    router.push(newPath);
  }

  return (
    <div>
      <button onClick={() => switchTo("en")} aria-current={locale === "en"}>EN</button>
      <button onClick={() => switchTo("ja")} aria-current={locale === "ja"}>JP</button>
    </div>
  );
}
```

`proxy.ts` reads the `NEXT_LOCALE` cookie (set by `next-intl` on navigation) and uses it as the fallback locale on the next visit. No flag icons, since flags map to countries, not languages.

## Date and number formatting

`next-intl`'s `useFormatter()` reads the active locale, so no additional library is needed.

```ts
const format = useFormatter();
format.dateTime(createdAt, { dateStyle: "medium" });
// "May 21, 2026"  ->  "2026年5月21日"
```

## Mobile layouts

The ticket tables and desk sidebar use fixed-width, desktop-first layouts that overflow on narrow viewports. Each gets a responsive variant at the `sm` breakpoint and below; the desktop layouts stay unchanged.

### Ticket list

Replace the fixed-width tables on `/tickets`, `/desk`, and `/admin/tickets` with a card layout at `sm` and below:

```
┌─────────────────────────────────┐
│ #001 · OPEN · HIGH              │
│ Cannot log in to the portal     │
│ Assigned: Dan Support · 2h ago  │
└─────────────────────────────────┘
```

- Priority and status rendered as coloured badges (same classes as desktop).
- Subject as the primary text.
- Assignee and relative time as the secondary line.
- Tap the card to navigate to the ticket detail.

### Users table

Replace the manager users table on `/admin/users` (name, email, role, actions) with a stacked card at `< sm`:

```
┌─────────────────────────────────┐
│ Dan Support                     │
│ dan@example.com · SUPPORT       │
│                     [Edit role] │
└─────────────────────────────────┘
```

### Desk sidebar

On mobile the desk sidebar takes the whole screen and the ticket list is hidden. Instead:

- Add a `showSidebar` boolean in a `DeskLayout` client component wrapping both panels.
- A header-mounted toggle button (filter or menu icon) flips `showSidebar`.
- When `showSidebar` is true the sidebar slides in as a fixed overlay and the list is hidden.
- When a ticket is selected from the sidebar, `showSidebar` becomes false to reveal the detail.

### Touch targets

Size the comment form, status buttons, and attach button for thumb use across the ticket detail.

## What stays unchanged

The service layer, authorization logic, Prisma schema, and all business rules are locale- and device-agnostic. Internationalization and mobile layout are entirely UI-layer concerns.
